# 2026-10-30

## 在 vivo Xplay6 (3e5a38a5, Android 7.1.1) 的 Termux 上成功构建 Voice app

- Termux 0.118.3 全新环境：换清华镜像，装 openssh/openjdk-25/aapt2/libc++/unzip
- 通过 `run-as com.termux`（该 ROM 允许）启动 sshd 并注入公钥，之后走 `ssh -p 8022 localhost`
- SDK 方案：本机打包 platforms/android-37.0 + build-tools/36.0.0 + licenses（~300MB）adb push 过去；aapt2 用 Termux 仓库的 ARM64 包（需先 `apt install libc++` 修复 `__ndk1` 链接错误），通过 `android.aapt2FromMavenOverride` 指定
- 依赖：本机 `~/.gradle/caches/modules-2`（1.2GB）打包推送；gradle-9.7.1 发行目录也直接推（免下载）
- 项目侧手机端覆盖（gradle.properties 追加）：jvmargs -Xmx2048m/Metaspace 384m、kotlin.daemon.jvmargs -Xmx1280m、workers.max=2、vfs.watch=false、aapt2 override、**org.gradle.priority=normal**（项目默认 low 会被 Android LMK 杀守护进程）
- app/build.gradle.kts 的 splits.abi 在手机端改为 `isEnable = false`，只出 universal 包
- 结果：BUILD SUCCESSFUL in 17m49s（476 tasks），app-free-debug.apk 22MB，装到本机并成功启动到中文引导页
- 坑：首次 2.5G+1.5G 内存配置被 LMK 杀 Gradle daemon；aapt2 libc++ 符号缺失；adb 传参引号会被吃（需 `adb shell "run-as ... sh -c '...'"` 双层引号）；versionCode 默认 Int.MAX_VALUE（2147483647），后续装低版本会报 downgrade
- 可复用流程已沉淀为技能 `termux-android-build`

## 构建默认值调整 (app/build.gradle.kts, AGENTS.md)
- ABI splits 默认关闭:只构建 universal 通用包;`-Pvoice.abiSplits=true` 恢复按 ABI 拆分。
- `assembleRelease` 重定向为仅依赖 `assembleFreeRelease`(afterEvaluate 中 setDependsOn,若任务不存在则注册)。
- 已用 dry-run 和实际 debug 构建验证:默认仅产出 app-free-debug.apk;开启属性后产出各 ABI + universal。
